04 Four Cases, One Pattern 4 นาที

ไล่เร็ว 3 เคสแรก เคสละ 20 วินาที แล้วลงน้ำหนักที่ Asahi

Stellantis: "ข้อมูลรั่วจากแพลตฟอร์มของผู้ให้บริการภายนอก ไม่มีสายการผลิตหยุด"

Bridgestone: "ผู้ผลิตยาง หยุดหลายโรงงานทั้งอเมริกาเหนือและใต้ — พอ supplier หยุด คนที่รอของก็หยุดตาม"

Asahi ลงน้ำหนัก "บริษัทญี่ปุ่นครับ ระบบสั่งซื้อ จัดส่ง และการผลิตหยุดเกือบทุกโรงงานจาก 30 แห่งทั่วญี่ปุ่น

สิ่งที่ผมอยากให้จินตนาการคือ เขากลับไปรับออเดอร์ด้วยกระดาษกับแฟกซ์ และระบบกว่าจะกลับมาครบก็เดือนกุมภาพันธ์ปีนี้"

เว้น 3 วินาที แล้วถามเบา ๆ ไม่ต้องรอคำตอบ: "ถ้าเป็นที่นี่ เราจะรับออเดอร์ยังไงครับ"

JLR: "หยุดผลิต 5 สัปดาห์ ยอดผลิตรถทั้งประเทศอังกฤษเดือนกันยายนลดลง 27% แย่ที่สุดนับตั้งแต่ปี 1952 และกระทบ supplier ประมาณ 5,000 ราย ส่วนใหญ่เป็นรายเล็ก"

ปิด: "สี่เคส วิธีเดียวกันหมดครับ — มีอะไรบางอย่างเปิดอยู่ มีบัญชีถูกใช้ แล้วสายการผลิตก็หยุด"

10 Start With Just a Domain Name 5 นาที

สไลด์ที่ต้องขออนุญาตก่อนใช้

เปิด: "ก่อนไปเรื่องทางออก ผมอยากให้ดูอย่างหนึ่งครับ เราลองทำในสิ่งที่ผู้โจมตีทำเป็นขั้นแรกเสมอ เริ่มจากชื่อโดเมนของ HMMT ชื่อเดียว ไม่ได้เข้าระบบอะไรเลย"

Map: "เราเห็นว่าเว็บ เมล DNS และ file transfer ทั้งหมดวิ่งกลับไปที่เครื่องเดียวกัน ซึ่งไม่ได้อยู่ในศูนย์ข้อมูลของ HMMT"

Enumerate: "บันทึกใบรับรองสาธารณะบอกชื่อระบบที่เคยออกใบรับรองไปทั้งหมด ไม่มีใครลบได้ ไม่ต้องขอใคร"

Fingerprint: "มีหน้าจัดการโฮสติ้งที่ตอบกลับจากอินเทอร์เน็ต และตอบผ่านช่องทางที่ไม่ได้เข้ารหัส แปลว่าใครก็ตามที่ล็อกอินวันนี้ ส่งรหัสผ่านไปแบบไม่มีการเข้ารหัส" ลึกที่สุดแค่นี้

Assess Trust: "โดเมนนี้ยังไม่มี record ที่บังคับให้ระบบปลายทางปฏิเสธเมลปลอม แก้ได้ด้วย DNS record หนึ่งบรรทัด"

ปิด: "ทั้งหมดนี้ใช้เวลาไม่ถึงบ่ายเดียว จากโดเมนเดียว โดยไม่ต้องขออะไรจากใครเลย

คำถามที่ผมอยากทิ้งไว้คือ ทั้งองค์กรมีอีกกี่ชื่อที่เราไม่เคยดู และถ้ามีอะไรเปลี่ยน เราจะรู้ภายในกี่วันครับ"

2. "มีเคสที่ OT โดน ransomware จนสายหยุดจริง ๆ ไหม" ใหม่

"มีครับ แต่แยกได้สองแบบ

แบบแรกคือหยุดเพราะระบบ IT ที่ OT พึ่งพาล่ม หรือทีมสั่งปิดเองเพื่อกันลาม — Norsk Hydro ปี 2019 กลับไปเดินเครื่องด้วยมือ, JBS ปี 2021 โรงงานแปรรูปหยุดหลายประเทศ, และ JLR กับ Asahi ปีที่แล้ว แบบนี้คือส่วนใหญ่

แบบที่สองคือมัลแวร์ที่ออกแบบมาแตะ OT โดยตรง — เคสคลาสสิกคือ Honda ปี 2020 ที่มัลแวร์ชื่อ EKANS มีรายการ process ของ ICS ฝังอยู่ในตัว ทำให้ต้องหยุดผลิตหลายโรงงาน

แต่ที่น่าสนใจคือ Honda ยังถูกยกเป็นข้อยกเว้นมาจนถึงวันนี้ ส่วนที่เกิดซ้ำทุกปีคือแบบแรก — ซึ่งเป็นเหตุผลที่ผมเอาสไลด์ dependency map มาให้ดูครับ"

3. "OT เราไม่ได้ต่อเน็ตอยู่แล้ว"

"ดีครับ นั่นช่วยได้มาก — แต่คำถามไม่ใช่ว่า OT ต่อเน็ตไหม คำถามคือ OT พึ่ง IT ตัวไหนอยู่

ERP ที่สั่งงานผลิต, file server ที่เก็บ recipe หรือ program, directory ที่ใช้ล็อกอินเข้า HMI, virtualization ที่รันทุกอย่าง — ถ้าตัวใดตัวหนึ่งล่ม สายก็หยุดโดยที่ OT ไม่ต้องต่อเน็ตเลยครับ"

4. "แล้วเราต้องซื้ออะไรเพิ่ม"

"ยังตอบไม่ได้ครับ และไม่ควรตอบวันนี้ด้วย เพราะเรายังไม่ได้ยืนยันว่าช่องว่างอยู่ตรงไหนจริง ๆ สี่ข้อใน Quick Wins ไม่ต้องซื้ออะไรเลย ผมอยากให้เริ่มจากตรงนั้นก่อนครับ"

5. "ทำ external review แบบนี้ได้เหรอ ผิดกฎหมายไหม"

"เป็นข้อมูลสาธารณะทั้งหมดครับ ใบรับรองที่ออกไปแล้วถูกบันทึกใน public log ที่ใครก็ดูได้ DNS ก็เปิดสาธารณะอยู่แล้ว ส่วนการทดสอบ TLS เราขออนุญาตล่วงหน้าก่อนทำ และไม่มีการทดสอบล็อกอินหรือรหัสผ่านใด ๆ" → เปิด Appendix A1

6. "ที่เจอมาทั้งหมด ร้ายแรงแค่ไหน"

"ระดับสูงสุดที่เราพบคือ High ครับ และเป็นเรื่อง hygiene เป็นหลัก ไม่ใช่ช่องโหว่ที่ถูกโจมตีได้ทันที ประเด็นของผมไม่ได้อยู่ที่ความร้ายแรงของแต่ละข้อ แต่อยู่ที่ว่ามันเห็นได้ง่ายแค่ไหนจากภายนอกครับ" → ถ้ายังอยากดู เปิด Appendix A2

7. "เรื่อง encryption กับ quantum ต้องทำตอนนี้เลยไหม"

"เป็นเรื่องระยะ 2030s ครับ ยังไม่ต้องรีบ แต่มีขั้นเตรียมหนึ่งที่ทำได้วันนี้และเป็นแค่การตั้งค่า ไม่ใช่โปรเจกต์" → เปิด Appendix A3 ใช้เป็นตัวเปิดหัวข้อสานต่อรอบหน้า

8. "สไลด์นี้ขอได้ไหม"

"ได้เลยครับ เดี๋ยวส่งให้พร้อมรายงาน" — ตอบรับเสมอ deck ออกแบบมาให้ส่งต่อได้ คำอธิบายทุกข้อเป็นประโยคสมบูรณ์ที่ยืนได้เอง
